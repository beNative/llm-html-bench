## 1. Overview & Core Workflow

LLM HTML Bench provides a persistent environment to answer critical questions about frontend AI generation:
- *Which model creates the cleanest, highest-quality interactive HTML applications?*
- *How does code quality and prompt adherence evolve across model releases and quantization levels?*
- *How do models perform on identical benchmark challenges over months or years?*

### The Benchmark Pipeline
```
[Prompt Task] ──► [Model Run Execution] ──► [Raw Response & HTML Extraction]
                          │
                          ▼
                 [Sandboxed Preview]
                          │
                          ▼
           [5-Dimension Multi-Score Rating]
                          │
                          ▼
         [Head-to-Head Comparative Ranking]
```

## 2. Dashboard & Leaderboards

The **Dashboard** serves as your central command view:
- **Top Metric Cards**: Displays live totals for Prompts, Registered Models, Benchmark Runs, Completed Evaluations, and Head-to-Head Matchups.
- **Model Performance Leaderboard**: Ranks all evaluated models based on their Average Overall Score, sample count ($n$), individual dimension averages (Visual Quality, Prompt Adherence, Functionality, Code Quality), and Head-to-Head Win Rates ($W-L$).
- **Category Breakdown**: Groups performance scores across categories (e.g. 3D & Games, Dashboards, Canvas, Complex Apps).
- **Recent Benchmark Runs**: Quick-access cards to inspect and compare recent generations with a single click.

## 3. Benchmark Prompts & Versioning

### Creating a Benchmark Prompt
1. Click **New Prompt** (or press `Ctrl+N`).
2. Provide a descriptive **Name** (e.g., *Interactive 3D Solar System*, *Real-time Audio Visualizer*).
3. Select a **Category** (General, Complex Interactive App, Games & Canvas, 3D & WebGL, Audio/Video & Media, Tool & Productivity, Data Visualization & Dashboards, Form & UI Component).
4. Enter the detailed **Prompt Text** in the built-in Monaco markdown editor.
5. Add comma-separated **Tags** and assign to **Collections** as desired.
6. Click **Create Prompt (v1)**.

### Immutable Versioning System
Prompt requirements evolve over time. LLM HTML Bench preserves historical integrity using immutable versioning:
- Every prompt starts at **Version 1 (v1)**.
- If you refine requirements or add constraints, create a **New Version** with changelog notes.
- Historical model runs remain permanently linked to the exact version of the prompt against which they were generated.

## 4. Registering Models

Track generations across specific provider architectures, parameter sizes, and quantization formats:
1. Click **New Model** (or navigate to the Models tab).
2. Enter the **Provider / Organization** (e.g., *Anthropic, OpenAI, Alibaba, Google, DeepSeek, Meta, Local*).
3. Enter the **Model Identifier** (e.g., `qwen3.8-27b`, `gpt-5.6`, `claude-3-7-sonnet`).
4. Set the **Deployment Type**: *Cloud API* or *Local Inference*.
5. (Optional) Provide **Model Family**, **Parameter Count** (e.g., `27B`, `70B`, `MoE`), **Quantization** (e.g., `FP16`, `Q4_K_M`, `NVFP4`), and Architecture Notes.
6. Click **Register Model**. The model appears immediately in the model catalog.

## 5. Recording Benchmark Runs

You can record benchmark outputs via **Manual Paste** (for web chats, command-line local models, or proprietary UI runs):
1. Click **Add Output** in the toolbar or inside a prompt view.
2. Select the **Target Prompt**, **Prompt Version**, and **Generating Model**.
3. (Optional) Record generation parameters: *Temperature*, *Top P*, *Generation Time (ms)*, *Output Tokens*, and *Tokens/Second*.
4. Paste the raw LLM response. The built-in parser automatically extracts clean HTML from markdown code fences (` ```html ... ``` `) while permanently preserving the original raw output.
5. (Optional) Provide initial ratings or save to score later in the Comparison view.
6. Click **Save Benchmark Output**.

## 6. Live API Execution

For automated, reproducible benchmarking directly from LLM endpoints:
1. Configure your endpoint in **Settings & DB** &rarr; **API Provider Configurations** (supports OpenAI, OpenRouter, LM Studio, Ollama, vLLM, and any OpenAI-compatible server). API keys are encrypted at rest using system-level `safeStorage`.
2. Click **Run Benchmark** in the header.
3. Select your provider, target prompt, prompt version, and target model.
4. Set sampling parameters (*Temperature*, *Top P*, *Max Tokens*).
5. Click **Start Execution**. LLM HTML Bench streams the request, captures timing and token telemetry, parses the generated HTML, and immediately opens the inspection view.

## 7. Side-by-Side Comparison & Inspector

The **Compare Mode** is the heart of the inspection laboratory:
- **Select up to 4 runs** simultaneously to compare side-by-side.
- **Synchronized Viewport Modes**: Toggle between *Responsive Canvas*, *Desktop (1920×1080)*, *Tablet (768×1024)*, and *Mobile (375×667)*.
- **Isolated Sandboxed Execution**: Each run executes in an independent, security-isolated iframe with strict script sandboxing.
- **Console & Error Drawer**: Real-time monitoring captures runtime JavaScript errors, warnings, and `console.log` statements for each model without polluting the main application.
- **Source Code Inspection & Monaco Diff Viewer**: Compare raw code or extracted HTML side-by-side with visual line and word diff highlighting.
- **Head-to-Head Matchup Arena**: Declare winners between model pairs (Left Wins, Right Wins, or Tie) to drive Elo-style win-rate rankings.

## 8. Evaluation Metrics & Scoring

Each benchmark run is evaluated across **5 core dimensions** on a 1–5 star scale:
1. **Visual Quality (25% weight)**: UI polish, typography, modern aesthetics, color harmony, visual layout, and animations.
2. **Prompt Adherence (25% weight)**: Strict compliance with all requirements, explicit constraints, and negative prompt conditions.
3. **Functionality (25% weight)**: Interactivity, working controls, state management, event handling, logic correctness, and zero JavaScript exceptions.
4. **Code Quality (15% weight)**: Clean architecture, single-file semantic structure, clean CSS/JS separation, and maintainability.
5. **Creativity / Polish (10% weight)**: UX delight, smooth transitions, micro-interactions, responsive design, and unexpected positive enhancements.

The **Overall Benchmark Score** is calculated as the weighted average across all 5 dimensions.

## 9. Collections & Tags

Organize your benchmarks systematically:
- **Collections**: Curate prompt test suites (e.g., *Frontend Coding Benchmark Suite 2026*, *3D WebGL Stress Tests*, *Mobile UI Suite*).
- **Tags**: Categorize tasks by technology or domain (`canvas`, `webgl`, `audio-api`, `single-file`, `game`, `reactive-state`).

## 10. Dataset Export, Import & Database Backups

- **Full JSON Dataset Export**: Export your complete benchmark repository (prompts, versions, models, runs, outputs, evaluations, comparisons) into a single transportable JSON file.
- **Dataset Import**: Merge or restore benchmark datasets non-destructively.
- **SQLite Database Backups**: Create point-in-time timestamped backups with one click in the Settings tab.
- **Database Optimization**: Vacuum and optimize the SQLite database engine directly from Settings.
